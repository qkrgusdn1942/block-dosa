# 12. 기술 구성

> 서버 없는 정적 웹. 게임 로직과 화면을 분리해서, 로직만 따로 테스트하고 봇으로 돌려볼 수 있게 한다.

## 스택 (안)
| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + TypeScript | 빠른 개발 서버, 타입으로 실수 줄이기 |
| 화면 | React | 장터, 부적, 결과처럼 화면 상태가 많음. 판(64칸)은 DOM으로 충분 |
| 스타일 | CSS (CSS 변수로 테마) | 애니메이션은 CSS transition, keyframes |
| 테스트 | Vitest | 점수 계산, 줄 지우기 단위 테스트 |
| 저장 | localStorage | 서버 없이 |
| 배포 | GitHub Pages ([qkrgusdn1942.github.io/block-dosa](https://qkrgusdn1942.github.io/block-dosa/)) | 무료 정적 호스팅. main에 push하면 Actions가 테스트·빌드·배포 |
| 설치 | PWA (홈 화면 추가) ✅ | 앱처럼 실행, 오프라인 실행, 아이폰 저장 데이터 보호 |

## 코드 구조 (안)
```
src/
  core/        순수 게임 로직 (DOM 없음 → 테스트, 봇 시뮬레이션 가능)
    board.ts     판 상태, 놓기 판정, 줄 지우기
    pieces.ts    블록 모양과 방향
    scoring.ts   족보 판정, 칩 × 배수 계산
    run.ts       런 진행 (고개·판·장터 흐름)
    shop.ts      장터 진열, 가격, 리롤
    effects.ts   부적·강화·요괴가 끼어드는 훅 처리
    rng.ts       시드 랜덤, 스트림 분리
  content/     데이터: 부적, 요괴, 블록, 목표 점수 표, 변경 사항(changelog.ts)
  ui/          React 화면, 드래그 입력, 연출
  save/        저장, 불러오기, 버전 이전
tests/         Vitest
scripts/       밸런스 확인용 봇 (npm run sim)
docs/          기획 문서
```
- 부적과 요괴는 "데이터 + 훅 함수"로 정의한다. 새 부적 추가 = content 파일에 항목 하나 추가.
- 테마 이름(도사, 요괴 등)은 content에만 둔다. 테마를 바꾸기 쉽다.

## 화면 흐름
- 타이틀 → 런 준비 → (판 미리보기 → 플레이 → 판 결과 → 장터) 반복 → 런 결과
- 플레이 중 실패하면 바로 런 결과 (🪶 봉황 깃털이 있으면 판 결과로)
- 고개 8 요괴를 깨면 끝낼지 고르기(victory) → 엔딩 → 런 결과, 또는 끝없는 모드로 계속

## 훅 (부적·요괴가 끼어드는 지점)
| 훅 | 시점 | 쓰는 예 |
|---|---|---|
| onRunStart | 런 시작 | 수련 "첫 인연" |
| onStageStart | 판 시작 | 🦊 구미호 봉인, 바위 배치 |
| adjustRules | 판 시작 (부적·수련·난이도 반영 뒤) | 💀 저승사자 |
| 방해 칸 onStageStart / onHandEnd | 판 시작 (바위·보너스 칸 다음) / 핸드 끝 (요괴 다음) | 🔒 자물쇠·🌿 이끼·💣 시한폭탄·🕸️ 저주 칸 놓기, 이끼 번지기, 폭탄 초읽기 (`src/content/obstacles.ts`) |
| onHandDraw | 핸드를 뽑을 때 | 👹 도깨비 모양 바꾸기, 🐅 장산범 가리기 |
| onPlace | 블록을 놓을 때 | 🧱 돌담 판정 |
| grow, onScore, onClearGold | 줄을 지울 때 (점수 계산 전 성장 → 계산 → 골드) | 대부분의 점수 부적, ⛄ 눈사람, 🐸 두꺼비 |
| onHandEnd | 핸드가 끝날 때 | 🌑 어둑시니, 🐍 이무기 |
| onStageClear | 판을 깼을 때 | 🎋 대나무, 👛 복주머니 |
| passive | 장착만 해도 | 🧺 키, 🍡 시루떡, 🎒 보따리, 🎁 덤, ✂️ 엿장수 가위, 🔮 여의주, 🪶 봉황 깃털 |
| 요괴 표시 | 판 내내 | 🐻 불가사리(강화 끄기), 🔥 강철이(골드 없음), 👊 두억시니(한 줄 0점) |

## 시드 랜덤
- 문자열 시드 → 해시(xmur3 등) → PRNG(mulberry32). 같은 시드면 같은 결과.
- 용도별로 스트림을 따로 만들어, 한 곳에서 랜덤을 많이 써도 다른 곳의 결과가 밀리지 않게 한다.

| 스트림 | 쓰는 곳 |
|---|---|
| bag | 블록 뽑기 순서와 방향 |
| shop | 장터 진열, 리롤 |
| board | 바위·보너스 칸 위치 |
| boss | 요괴 순서 |
| luck | 확률 효과 (윷가락, 유리, 행운, 📜 두루마리 칸의 비전서 등) |
| obstacle | 판의 방해 칸 종류 (런), 방해 칸 위치 (판 시작). 이끼·시한폭탄의 핸드 끝 효과는 boss 스트림을 같이 쓴다 (요괴 판에는 방해 칸이 없음) |
| skip, skip-study | 판 건너뛰기 보상, 족보 공부로 오르는 족보 |
| relic | 요괴 유품 (고개마다) |
| starter | 수련 "첫 인연" |
| bag-enhance | 혼돈 가방의 시작 강화 |
| endless-boss | 끝없는 모드 고개 9부터의 요괴 |

- 판마다 (시드, 고개, 판) 조합으로 스트림을 다시 만든다. 앞 판에서 한 행동이 다음 판의 블록 순서를 밀지 않는다.
- 오늘의 판 시드 = 한국 시간 날짜 (예: `D20261012`)

## 저장
- localStorage에 JSON으로 저장하고, 버전 번호를 넣어 업데이트 때 이전할 수 있게 한다.
- 블록을 놓을 때마다 저장한다 (데이터가 작아서 부담 없음).
- 세이브 코드 ✅ (v1.1, `src/save/transfer.ts`): localStorage에 저장된 글(프로필, 런)을 JSON으로 묶어 deflate-raw로 압축하고 base64url로 바꾼 뒤 `BDS1.`을 붙인다. 브라우저 기본 CompressionStream을 써서 라이브러리가 필요 없다. 넣을 때는 저장된 글 그대로 덮어쓰고, 읽는 쪽에서 버전 이전을 한다.

| 키 | 내용 |
|---|---|
| `block-dosa:run` | 진행 중인 런 (`version`, 런 id, 런 상태 전체). 런이 끝나면 지운다 |
| `block-dosa:profile` | 공덕, 수련, 기록. `lastSettledRun`으로 같은 런을 두 번 정산하지 않는다 |

- 런 상태 구조를 바꾸면 `SAVE_VERSION`(src/save/storage.ts)을 올리고, 예전 버전을 지금 구조로 올리는 이전 코드를 `migrate`에 넣는다. 올릴 수 없는 버전은 버린다.
- 버전 1 → 2 (v0.4): 런 종류(normal·daily·seed), 공식 여부, 판 결과 기록, 최고 한 방 족보, 끝판 표시를 기본값으로 채운다.
- 버전 2 → 3 (v1.0): 가방 종류(기본)·난이도(1)·끝없는 모드(아님), 보관함·핸드 크기, 장터 무료 리롤·가격, 블록 팩 선택지(모양 → {모양, 강화}), 해금 기록을 채운다.
- 버전 3 → 4 (v1.1): 주간 규칙(없음), 건너뛰기 쿠폰(없음), 도감 기록(지금 부적만), 판의 방해 칸(없음)·소모품 칸 수·되돌리기(없음, 남은 횟수 1), 마지막 클리어의 두루마리·저주 칸·빗자루 표시, 장터 공짜 팩·반값(아님)을 채운다.
- 프로필은 버전을 올리지 않고 기본값 위에 덮어 읽는다 (v1.0에 대청소 누적, 깬 난이도, 지난번 런 준비가 늘었다).
- 저장된 런을 그리다 오류가 나면 빈 화면 대신 안내를 띄우고, 그 런을 지운 뒤 처음 화면으로 돌아간다.

## 판 로직 메모 (v1.1)
- 줄 점수는 한 곳(`scoreCleared`, src/core/stage.ts)에서 계산한다. 블록 놓기·🐍 이무기 밀기는 `resolveClears`로 꽉 찬 줄을 찾아서, 🧹 빗자루는 고른 줄을 비운 뒤 같은 함수를 부른다. 어디서 왔는지는 `ClearSource`(piece / shift / broom)로 구분한다.
- ↩ 되돌리기: 블록을 놓을 때 놓기 직전 판 상태(`StageSnapshot`, 그 안의 되돌리기는 뺌)를 `stage.undo`에 넣는다. 놓기만 이 상태를 남기고, 다른 행동(🐅 가린 블록 드러내기 포함)은 비운다. 횟수는 `stage.undoLeft` (판마다 `FREE_UNDOS` = 1).

## 성능 원칙
- 실시간 게임 루프 없음. 상태가 바뀔 때만 다시 그린다.
- 판 64칸은 DOM(CSS Grid). 드래그 중인 블록만 transform으로 움직인다.
- 애니메이션은 transform, opacity만.
- 숫자: JS 기본 숫자로 약 1.8×10³⁰⁸까지 표현 가능. 점수·목표는 10³⁰⁰에서 멈춰서 JSON 저장이 깨지지 않게 한다. 그 너머가 필요해지면 큰 수 라이브러리(break_infinity.js) ⏳

## 홈 화면 설치 (PWA) ✅ (v1.0)
| 파일 | 내용 |
|---|---|
| `public/manifest.webmanifest` | 이름, 세로 화면, 색, 아이콘 (상대 경로라 `/block-dosa/` 아래에서도 그대로) |
| `public/icons/` | `icon.svg`(원본, 파비콘), 192·512 PNG, 마스크용 512 PNG, 아이폰용 180 PNG |
| `public/sw.js` | 서비스 워커. 페이지는 네트워크 먼저(새 배포가 바로 보임, 오프라인이면 캐시), 빌드 파일·아이콘은 캐시 먼저 |
| `src/ui/install.ts` | `beforeinstallprompt`를 받아 두었다가 처음 화면의 "홈 화면에 추가" 버튼으로 띄움. 아이폰은 사파리 공유 버튼 안내 |

- 서비스 워커는 배포본(`npm run build`)에서만 등록한다. 개발 서버에서는 캐시 때문에 헷갈리지 않게 등록하지 않는다.
- `sw.js`를 고치면 그 안의 `CACHE` 이름을 올려서 예전 캐시를 지운다.
- PNG 아이콘은 `icon.svg`를 macOS `qlmanage -t -s <크기>`로 그려서 만들었다. 아이콘을 바꾸면 SVG를 고치고 같은 방법으로 다시 만든다 (마스크용은 가운데 80% 안에 들어가게 블록을 작게).

## 모바일 웹 주의점
| 문제 | 대응 |
|---|---|
| 블록을 끄는 중에 화면이 스크롤되거나 당겨서 새로고침됨 | 게임 영역에 `touch-action: none`, `overscroll-behavior: none` |
| 더블탭하면 확대됨 | viewport 설정으로 확대 막기 |
| 주소창이 나타났다 사라지며 화면 높이가 바뀜 | `100dvh` 사용 |
| 아이폰 사파리는 7일 동안 안 들어간 사이트의 저장 데이터를 지울 수 있음 | 홈 화면 추가 안내, 세이브 코드 |
| 카톡 내장 브라우저는 저장 공간이 따로 | 시드·세이브를 코드 붙여넣기로 |
| 진동 API는 안드로이드만 | 아이폰에선 진동 없이 화면 효과만 |

## 테스트
- 단위 테스트: 줄 지우기, 족보 판정, 점수 계산 순서, 부적 효과, 같은 시드면 같은 결과가 나오는지
- 봇 시뮬레이션 ✅ (v1.1): `scripts/bot.ts`가 core만으로 런을 끝까지 둔다. `npm run sim`(설정 `vitest.sim.config.ts`)이 고개 도달률과 판별 통과율(방해 칸 유무 포함)을 찍는다. 평소 `npm test`에는 안 들어간다 → [08. 난이도](08-difficulty.md)
- 봇의 습관(`BotOptions`: 사서 쓰는 소모품 종류, 판 1 건너뛰기)을 바꿔 가며 비교할 수 있다. 조정 전후 비교는 반드시 같은 시드로 한다 (시드 묶음만 바꿔도 도달률이 몇 %p 움직인다).
