# 12. 기술 구성

> 서버 없는 정적 웹. 게임 로직과 화면을 분리해서, 로직만 따로 테스트하고 봇으로 돌려볼 수 있게 한다.

## 스택 (안)
| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + TypeScript | 빠른 개발 서버, 타입으로 실수 줄이기 |
| 화면 | React | 장터, 부적, 결과처럼 화면 상태가 많음. 판(64칸)은 DOM으로 충분 |
| 스타일 | CSS (CSS 변수로 테마) | 애니메이션은 CSS transition, keyframes |
| 테스트 | Vitest | 점수 계산, 줄 지우기 단위 테스트 |
| 저장 | localStorage | 서버 없이 |
| 배포 | GitHub Pages ([qkrgusdn1942.github.io/block-dosa](https://qkrgusdn1942.github.io/block-dosa/)) | 무료 정적 호스팅. main에 push하면 Actions가 테스트·빌드·배포 |
| 설치 | PWA (홈 화면 추가) ⏳ | 앱처럼 실행, 아이폰 저장 데이터 보호 |

## 코드 구조 (안)
```
src/
  core/        순수 게임 로직 (DOM 없음 → 테스트, 봇 시뮬레이션 가능)
    board.ts     판 상태, 놓기 판정, 줄 지우기
    pieces.ts    블록 모양과 방향
    scoring.ts   족보 판정, 칩 × 배수 계산
    run.ts       런 진행 (고개·판·장터 흐름)
    shop.ts      장터 진열, 가격, 리롤
    effects.ts   부적·강화·요괴가 끼어드는 훅 처리
    rng.ts       시드 랜덤, 스트림 분리
  content/     데이터: 부적, 요괴, 블록, 목표 점수 표
  ui/          React 화면, 드래그 입력, 연출
  save/        저장, 불러오기, 버전 이전
tests/         Vitest
docs/          기획 문서
```
- 부적과 요괴는 "데이터 + 훅 함수"로 정의한다. 새 부적 추가 = content 파일에 항목 하나 추가.
- 테마 이름(도사, 요괴 등)은 content에만 둔다. 테마를 바꾸기 쉽다.

## 화면 흐름
- 타이틀 → 런 준비 → (판 미리보기 → 플레이 → 판 결과 → 장터) 반복 → 런 결과
- 플레이 중 실패하면 바로 런 결과
- 고개 8 요괴를 깨면 엔딩 → 런 결과

## 훅 (부적·요괴가 끼어드는 지점)
| 훅 | 시점 | 쓰는 예 |
|---|---|---|
| onRunStart | 런 시작 | 수련 "첫 인연" |
| onStageStart | 판 시작 | 🦊 구미호 봉인, 바위 배치 |
| onHandDraw | 핸드를 뽑을 때 | 👹 도깨비 모양 바꾸기 |
| onPlace | 블록을 놓을 때 | 🧱 돌담 판정 |
| onClear | 줄을 지울 때 (점수 계산) | 대부분의 점수 부적 |
| onHandEnd | 핸드가 끝날 때 | 🌑 어둑시니, 🐍 이무기 |
| onStageEnd | 판이 끝날 때 | 🎋 대나무, 👛 복주머니 |
| onShopEnter, onReroll | 장터 | ✂️ 엿장수 가위 |

## 시드 랜덤
- 문자열 시드 → 해시(xmur3 등) → PRNG(mulberry32). 같은 시드면 같은 결과.
- 용도별로 스트림을 따로 만들어, 한 곳에서 랜덤을 많이 써도 다른 곳의 결과가 밀리지 않게 한다.

| 스트림 | 쓰는 곳 |
|---|---|
| bag | 블록 뽑기 순서와 방향 |
| shop | 장터 진열, 리롤 |
| board | 바위·보너스 칸 위치 |
| boss | 요괴 순서 |
| luck | 확률 효과 (윷가락, 유리, 행운 등) |

- 판마다 (시드, 고개, 판) 조합으로 스트림을 다시 만든다. 앞 판에서 한 행동이 다음 판의 블록 순서를 밀지 않는다.
- 오늘의 판 시드 = 한국 시간 날짜 (예: `D20261012`)

## 저장
- localStorage에 JSON으로 저장하고, 버전 번호를 넣어 업데이트 때 이전할 수 있게 한다.
- 블록을 놓을 때마다 저장한다 (데이터가 작아서 부담 없음).
- 세이브 코드: JSON을 압축해서 문자열로 (기기 이동, 백업용) ⏳

| 키 | 내용 |
|---|---|
| `block-dosa:run` | 진행 중인 런 (`version`, 런 id, 런 상태 전체). 런이 끝나면 지운다 |
| `block-dosa:profile` | 공덕, 수련, 기록. `lastSettledRun`으로 같은 런을 두 번 정산하지 않는다 |

- 런 상태 구조를 바꾸면 `SAVE_VERSION`(src/save/storage.ts)을 올리고, 예전 버전을 지금 구조로 올리는 이전 코드를 `migrate`에 넣는다. 올릴 수 없는 버전은 버린다.
- 버전 1 → 2 (v0.4): 런 종류(normal·daily·seed), 공식 여부, 판 결과 기록, 최고 한 방 족보, 끝판 표시를 기본값으로 채운다.
- 저장된 런을 그리다 오류가 나면 빈 화면 대신 안내를 띄우고, 그 런을 지운 뒤 처음 화면으로 돌아간다.

## 성능 원칙
- 실시간 게임 루프 없음. 상태가 바뀔 때만 다시 그린다.
- 판 64칸은 DOM(CSS Grid). 드래그 중인 블록만 transform으로 움직인다.
- 애니메이션은 transform, opacity만.
- 숫자: JS 기본 숫자로 약 1.8×10³⁰⁸까지 표현 가능. 끝없는 모드에서 넘어가면 큰 수 라이브러리(break_infinity.js) ⏳

## 모바일 웹 주의점
| 문제 | 대응 |
|---|---|
| 블록을 끄는 중에 화면이 스크롤되거나 당겨서 새로고침됨 | 게임 영역에 `touch-action: none`, `overscroll-behavior: none` |
| 더블탭하면 확대됨 | viewport 설정으로 확대 막기 |
| 주소창이 나타났다 사라지며 화면 높이가 바뀜 | `100dvh` 사용 |
| 아이폰 사파리는 7일 동안 안 들어간 사이트의 저장 데이터를 지울 수 있음 | 홈 화면 추가 안내, 세이브 코드 |
| 카톡 내장 브라우저는 저장 공간이 따로 | 시드·세이브를 코드 붙여넣기로 |
| 진동 API는 안드로이드만 | 아이폰에선 진동 없이 화면 효과만 |

## 테스트
- 단위 테스트: 줄 지우기, 족보 판정, 점수 계산 순서, 부적 효과, 같은 시드면 같은 결과가 나오는지
